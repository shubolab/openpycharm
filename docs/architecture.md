# 产品基础与实现边界

OpenPyCharm 的目标是参考本机 PyCharm 2026.1.4，构建自己的原生 Python 桌面 IDE。窗口、编辑器、动作、撤销、项目管理和工具窗口由开源 IntelliJ Platform 提供；Python 的解析器、PSI、类型分析、解释器、运行、测试和调试使用开源 PyCharm 的实现。

产品基础固定为 [JetBrains/intellij-community 的 pycharm/2026.1.4 发行](https://github.com/JetBrains/intellij-community/releases/tag/pycharm/2026.1.4)。下载的安装资源通过固定大小与 SHA-256 校验后才可作为构建输入。它与本机安装的统一 PyCharm 是两个独立来源：本机应用只用于只读核对可见行为，不能把其商业插件或其他私有实现复制进发行包。

## 工程职责

| 部分 | 职责 |
| --- | --- |
| `product/platform.lock.json` | 固定开源基础的版本、平台、下载来源、大小与摘要 |
| `scripts/bootstrap.py` | 获取与校验基础安装资源，准备项目拥有的开发/打包输入 |
| 产品组装脚本 | 在项目拥有的副本中应用 OpenPyCharm 名称、启动器、配置目录与产品资源，保留上游和第三方声明 |
| `fixtures/hello-python` | 用同一个小项目检查编辑、导航、重构、运行、测试、调试与控制台 |
| `docs/acceptance.md` | 区分功能目标、实际桌面证据与未完成范围 |

opengoland 已解决了原生独立产品的安装输入校验、产品身份、可重定位启动、安装器和证据留存等问题，这些工程方法可以复用。Go 引擎、gopls 与 Delve 不承担 Python 语言功能；Python 集成沿用开源 PyCharm 的原生能力。Go 产品的模块清单、二进制摘要和资源补丁不能直接当作 PyCharm 的验证结果，必须针对本产品的实际输入重新核对。

## 产品行为

应用使用 OpenPyCharm 独立的名称、标识和配置/缓存路径，使它能够与参考 PyCharm 并存。用户的参考应用、许可状态、配置和项目数据保持原样。发行时应保留 Git、GitHub 以及用户主动选择的其他开发服务认证；IDE 账号、试用、订阅、收费和商业升级推广按产品要求移除，并逐项检查原生入口。

首个完整链路应从校验过的开源基础组装开始，随后使用实际安装的应用打开示例项目，完成解释器选择、运行、unittest、调试和退出。开发沙箱、源文件存在、插件已打包或单元测试通过仅证明各自范围，均不等于独立安装产品通过验收。

## 对齐范围

开源 PyCharm 提供了与参考应用同源的桌面基础和 Python 核心，因此可优先对齐日常 Python 开发流程。统一 PyCharm 中的框架、数据库、Notebook、前端、容器和远程功能需要逐项确认开源可用范围；缺失部分以独立实现或合适的开源组件补齐，并记录兼容性和行为差异。

当前文档定义的是构建路线与验收约束，没有宣称完整 1:1 对齐已经完成。具体状态以[验收矩阵](acceptance.md)和对应版本的实际证据为准。
